# CSI machine-learning baseline

This module provides an initial, reproducible baseline for the Intel VHT
dataset. It is an experiment for the current three labels, not a validated
production detector.

For a reader-friendly map of the Task 3 pose/activity reports, result folders,
metrics, and limitations, see the
[Task 3 research and results guide](results/pose-sync-check/HUONG_DAN_DOC_VA_KET_QUA_TASK3.md).

The original `Final_CSI` captures and local virtual environments are not
included in this repository. The published reports, compact evaluation
metrics, and figures can be inspected after cloning, but reproducing the
training runs requires separately obtaining compatible CSI data and following
the signal-processing setup.

## What it evaluates

- **Three-class task:** `room_empty`, `person_static`, `person_moving`.
- **Presence task:** `room_empty` vs. `person_present` (static and moving are
  combined).
- **Models:** Logistic Regression and Random Forest.
- **Feature sets:** temporal features only, and frame-level plus temporal
  features.
- **Validation:** leave one entire recording session out at a time. Frames
  from the held-out session are never used for training or scaling.

The script fits imputation, scaling, and each model inside every training fold.
Do not pass the pipeline's globally normalized CSVs; use the raw feature tables
so statistics are learned only from each fold's training sessions.

## Run from the repository root

First install the signal-processing requirements and create the CSVs, following
the parser → preprocessing pipeline steps in
[`../signal-processing/README.md`](../signal-processing/README.md). Then install
the ML requirements and run:

```powershell
python -m pip install -r machine-learning/requirements.txt
python machine-learning/src/train_baseline.py
```

By default, the script reads:

- `signal-processing/data/intel/data/processed/preliminary_frame_features.csv`
- `signal-processing/data/intel/data/processed/temporal_features.csv`

The outputs are written to `machine-learning/results/baseline/`:

- `summary_metrics.csv` — pooled out-of-fold and mean-per-session metrics.
- `per_session_metrics.csv` — metrics for each held-out recording.
- `out_of_fold_predictions.csv` — one prediction per held-out frame.
- `confusion_matrices.csv` — counts by actual/predicted class and held-out
  session.
- `random_forest_confusion_matrices.png` — pooled confusion matrices for both
  tasks, using the Random Forest with frame + temporal features.
- `random_forest_session_accuracy.png` — held-out accuracy for each recording
  session, for both tasks.

For custom locations:

```powershell
python machine-learning/src/train_baseline.py `
  --processed-dir signal-processing/data/intel/data/processed `
  --output-dir machine-learning/results/baseline
```

Run the focused tests with:

```powershell
python -m pytest -q machine-learning/tests
```

## First baseline result on the current Intel sessions

The first run used all 9 sessions (5,053 complete frames) after the documented
parser and preprocessing steps:

| Task | Model | Features | Pooled balanced accuracy | Pooled macro F1 |
|---|---|---|---:|---:|
| Three classes | Random Forest | Frame + temporal | 0.953 | 0.952 |
| Three classes | Logistic Regression | Frame + temporal | 0.881 | 0.877 |
| Presence | Random Forest | Frame + temporal | 0.984 | 0.981 |
| Presence | Logistic Regression | Frame + temporal | 0.923 | 0.892 |

Temporal-only features scored lower than the combined feature set for the
three-class task (Random Forest balanced accuracy 0.842 vs. 0.953). In the
three-class Random Forest run, held-out session accuracy ranged from 0.804 to
0.996; the two weakest sessions were `person_static_03` (0.804) and
`person_static_02` (0.872). This variation is important and should not be hidden
by the pooled score.

These are exploratory, session-held-out results on recordings from one
collection setup. They do **not** establish performance in another room, with
another person or device placement, on event-level motion labels, or for
multi-person counting. Report the per-session scores and these limitations
alongside the pooled metrics. The CSV output files are generated artifacts and

The chart files are generated by the training script. In a confusion matrix,
the rows are actual labels, the columns are predicted labels, and each cell
shows the frame count and share of that actual class. The session chart gives
each whole recording its own bar; it helps expose variation that a pooled
score can hide. Frames within a session are correlated, so neither the counts
nor the bars represent independent recording trials. The CSV output files are generated artifacts and
are excluded by the repository's `*.csv` ignore rule; rerun the documented
command to regenerate them.

## Interpretation limits

There are currently only three recording sessions per Intel class. The
leave-one-session-out scores are a useful first comparison, not a strong
estimate of future performance. Frames in the same recording are temporally
correlated, so frame-level counts must not be presented as independent trials.
The session-level metrics and per-session results should be reported alongside
the pooled metrics.

The current data supports experiments on presence/static/moving only. It does
not support claims about people counting, gender, height, or reliable
multi-person detection. Collect more independent sessions, including the
intended multi-person conditions, before evaluating those goals.

## Exploratory activity-classification prototype

The activity-classification experiment uses six session labels: `empty`,
`standing`, `left_arm`, `right_arm`, `walking`, and `mixed`. Its saved
leave-one-round-out evaluation and limitations are documented in the
[activity results report](results/activity-round-experiment/round-heldout-comparison/ACTIVITY_CLASSIFICATION_RESULTS.md).
This experiment classifies session activity labels; it does **not** predict a
person's joint coordinates or the exact time of a live action transition.

Run from the repository root after running the signal-processing pipeline:

```powershell
python machine-learning/src/train_activity_baseline.py `
  --processed-dir signal-processing/data/pose/data/processed
```

For later recording rounds, put each new CSI session under
`signal-processing/csi-data/labeled/` with its unique `trial`, and keep the
matching `video-session-notes.txt` containing `activity`, `repeat`,
`participant_id`, and `session_id`. Then run the activity-only pipeline:

```powershell
python machine-learning/src/run_activity_pipeline.py
```

This command rebuilds the session index, parses every available VHT session,
recomputes the feature tables, evaluates, and retrains the prototype. It stops
and reports the failed stage instead of training on stale features. This mode
does not require a video or screen-clock because it is for session-level
activity classification only; it cannot prepare pose/keypoint targets.

For per-frame inference on processed CSI features:

```powershell
python machine-learning/src/predict_activity.py `
  --processed-dir signal-processing/data/pose/data/processed `
  --model machine-learning/results/activity-baseline/activity_classifier_prototype.joblib `
  --output machine-learning/results/activity-baseline/predictions.csv
```

The inference command does not need ground-truth activity labels. It joins the
complete frame and temporal features by `session_id` and `frame_id`, then
outputs `predicted_activity` for each frame. It expects CSI to have already
gone through the same parser and feature pipeline used for training. The
prototype model expects the feature columns listed in `model_metadata.json`.

By default, outputs are saved under
`machine-learning/results/activity-baseline/`. The script compares a
most-frequent dummy classifier, Logistic Regression, and Random Forest using
temporal-only and frame-plus-temporal features. Validation holds out contiguous
time blocks within each recording and removes a 20-frame guard around each
held-out block to reduce overlap from the 2-second temporal feature window.
The output includes pooled metrics, per-session scores, out-of-fold predictions,
confusion-matrix counts, Random Forest feature importance, a confusion-matrix
chart, and a prototype Random Forest trained on all current rows.

**Important limitation:** there is currently only one recording session per
activity. Therefore, the held-out blocks still come from sessions represented
in training. These metrics are an exploratory within-recording check, not an
estimate of performance on a new session, participant, room, or device setup.
The session-level activity label is copied to each frame; in particular,
`mixed` does not have event-level labels. Do not present these scores as
validated action recognition. The saved Random Forest is a prototype trained
on all available rows and must be retrained and independently evaluated when
more sessions and synchronized pose labels become available.

To add future activity sessions, place each labeled session in the input to
the signal-processing pipeline, regenerate both feature CSVs, then rerun the
training command. Keep new session IDs distinct and ensure each session has
one activity label. Do not use the generated prototype for a new participant
or recording as a validated result until independent-session evaluation has
been performed.

## Person 3: CSI-to-pose baseline

The activity classifier above is **not** the pose model. The Person 3 baseline
maps a synchronized CSI window to normalized 2D MediaPipe keypoints and a
person-present prediction. It compares a training-set mean-pose baseline with
per-joint Ridge regression, and reports person-presence metrics separately.

The delivered NPZ package is in
`signal-processing/data/pose/data/pose_windows_dataset/`. The trainer accepts
both its legacy pixel-coordinate schema (`keypoints`, 33 MediaPipe landmarks)
and the newer normalized-coordinate schema (`keypoints_normalized`). It maps
landmarks by name to the 17 COCO-ordered keypoints and joins
`windows_index.csv` for per-window timestamps, presence labels, and sync flags.
For legacy pixel coordinates, the documented source video size of 1920×1080 is
used to normalize coordinates; override it with `--image-width` and
`--image-height` if the source resolution differs.

The current package marks synchronization as unverified. The trainer therefore
rejects those windows by default. To run a **diagnostic-only** baseline on the
provided package, from the repository root run:

```powershell
python machine-learning/src/train_pose_baseline.py `
  --allow-unverified-sync
```

This command does not rebuild or alter the Person 2 package. It runs
leave-one-session-out evaluation and fits the prototype model. Its outputs are
saved under
`machine-learning/results/pose-baseline-exploratory/` and are explicitly
marked as diagnostic; do not report the scores as valid pose accuracy until
the CSI/video synchronization is verified. For a strict run, omit
`--allow-unverified-sync`; the trainer will only use `sync_ok=1` windows.
The model predicts single-person 2D joints and presence; this package does not
support people counting, gender, or height estimation.

Generate a chart from the latest saved metrics with:

```powershell
python machine-learning/src/plot_pose_diagnostic.py
```

The chart is saved as
`machine-learning/results/pose-baseline-exploratory/pose_baseline_diagnostic.png`.
It compares the mean-pose and Ridge baselines, shows scores per held-out
session, and includes the separate person-presence metrics. The chart labels
the current run as diagnostic-only because synchronization is unverified.

Run inference on preprocessed CSI windows with:

```powershell
python machine-learning/src/predict_pose.py `
  --input-npz path\to\new_csi_windows.npz `
  --model machine-learning/results/pose-baseline-exploratory/pose_baseline.joblib `
  --output machine-learning/results/pose-baseline-exploratory/predictions.csv
```

For an already-recorded CSI session folder containing `raw.csi`,
`recorder.log`, and `metadata.txt`, build the same 2-second/0.2-second VHT
windows and run inference in one command:

```powershell
python machine-learning/src/predict_pose_session.py `
  --input-session "D:\CSI values\Final_CSI\path\to\labeled\session" `
  --model machine-learning/results/pose-sync-check/final-csi-rebuild/retrained-verified-lan2-lan3-20261110/pose_baseline.joblib `
  --output machine-learning/results/raw-session-inference/predictions.csv
```

The command writes a compressed window archive next to the predictions, checks
the CSI record count through the signal-processing parser, and rejects windows
that cross a gap longer than 300 ms. It also writes a `_metrics.json` sidecar
with parse/window, archive, inference/CSV, and total elapsed times. This is an
offline path for a saved capture; it does not connect to a live receiver or make
the pose model CSI-conditioned when the selected coordinate baseline is
`training_mean`.

Run the pose baseline tests with:

```powershell
python -m pytest -q machine-learning/tests/test_pose_baseline.py
python -m pytest -q machine-learning/tests/test_predict_pose_session.py
```

Each training run preserves an immutable snapshot under
`machine-learning/results/activity-baseline/runs/<run_id>/`, including its
metrics, metadata, and model. `run_history.csv` records the validation mode,
data size, balanced accuracy, and snapshot path. The top-level model and
metrics are the latest run for convenience; use a model inside `runs/<run_id>`
to reproduce an earlier prediction.

The CSI pipeline's five-frame moving average is an offline filtering
**evaluation**, not the source of the feature CSVs used here. The model uses
the unfiltered frame and temporal feature tables. Compare raw and filtered
inputs only after the filtering choice and live inference behavior are agreed.

### First result on the current six CSI sessions

The run used 3,489 complete CSI frames from six sessions, one session per
activity. With frame-plus-temporal features, the guarded within-session
balanced accuracy was 0.811 for Random Forest and 0.794 for Logistic
Regression; the most-frequent dummy baseline was 0.167. Temporal-only
balanced accuracy was 0.578 for Random Forest and 0.591 for Logistic
Regression.

Random Forest frame-plus-temporal accuracy by recording was: `empty` 1.000,
`standing` 0.943, `left_arm` 0.916, `right_arm` 0.892, `mixed` 0.577, and
`walking` 0.541. These are exploratory scores on held-out time blocks from the
same recording sessions used for training, so they do not establish how the
model performs on a new recording. In particular, do not claim validated
recognition for `walking` or `mixed`; collect independent repeats and add
event-level activity timing before making such a claim.
